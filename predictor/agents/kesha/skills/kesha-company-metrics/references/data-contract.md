# Контракт анализа метрик

PostgreSQL — источник истины для строк метрик компании. Каждая строка содержит непрозрачный UUID `metric_id`, созданный PostgreSQL, `company_id`, `type_code`, `metric_type`, `characteristic`, `unit` и необязательные параметры. `type_code` следует общему порядку: `ставка`, `депозит`, `курс`, `логистика`, `цена`, `спрос`, `запас`, `контрагент`, `зарплата`. Не извлекай сведения о компании или типе из `metric_id`.

ClickHouse хранит новости, общие факты и связи с ними, а также наблюдения метрик. Наблюдение содержит `company_id`, непрозрачный `metric_id`, `news_id`, числовое `value` или `null`, вероятность или `null` и `source_fact_ids` (пустой список, если связанных ID фактов нет). Полей периода у наблюдения нет. ESB формирует стабильный ID наблюдения из компании, метрики, новости и ID исходных фактов; если разные прогнозы используют одинаковые ID фактов, передай отдельный `observation_id`. Время публикации, URL и тип источника берутся из связанной записи новости. Материал исследования соответствует `source_kind: research`, внешняя новость — `source_kind: external`.

## Расчёт

`calculate_metric_total` принимает только `metric_id`, `period_from` и `period_to`. Фильтрация выполняется по времени публикации связанной новости, обе границы включаются. Время добавления прогноза на период не влияет. Наблюдение исключается, если связанная новость или время публикации отсутствуют либо значение равно `null`. Ноль учитывается. Несколько наблюдений по одной новости каждое участвуют в среднем.

- `total_value` — `avgOrNull(value)` по выбранным наблюдениям. Вероятность не взвешивает значение.
- `total_probability` — `avgOrNull(probability)` по тем же наблюдениям; значения `null` исключаются только из этого среднего.
- `fact_count` — число выбранных ненулевых значений.
- `probability_count` — число выбранных ненулевых вероятностей.
- `links` содержит каждый выбранный `news_id` один раз, сортировка по времени новости и затем по ID. Отсутствие URL не исключает ссылку.

Если подходящих строк нет, итоги равны `null`, счётчики — нулю, список ссылок пуст. Не заменяй `null` нулём. Если `period_to` раньше `period_from`, верни такой же пустой результат и не меняй границы местами.

`calculate_all_metric_totals` читает настроенные строки компании из PostgreSQL в порядке каталога, вызывает первый расчёт для каждого UUID и возвращает `company_id`, границы периода и `items`. Каждый элемент содержит `metric_id`, `type_code`, `characteristic` и поля расчёта. Настроенная метрика без результатов всё равно остаётся в `items`; если у компании нет настроенных строк, верни пустой список `items`. Не усредняй значения разных настроенных метрик между собой.

Итоги вычисляются при каждом запросе и не сохраняются. Агент получает доступ к PostgreSQL, ClickHouse и S3 только через MCP-инструменты ESB.
